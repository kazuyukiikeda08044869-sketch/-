---

## ツイート2

```
【失敗①】要件定義を「上」だけでやる

経営層とITベンダーだけで要件を決めて、
実際に仕訳を切る人・経費精算する人が会議にいない。

結果：
「使いにくい」「現場の業務と合わない」
「結局Excelを使い続ける」

現場ヒアリングをケチったツケは、本番後に全部回ってくる。
```

---

## ツイート3

```
【失敗②】「カスタマイズすれば解決」と思ってる

ERPの強みは「標準機能で業務を回す」こと。

カスタマイズを重ねると：
・コストが膨らむ
・バージョンアップできなくなる
・そのカスタムを知ってる人が辞めたら詰む

「自社の業務に合わせる」より
「ERPの業務フローに自社を合わせる」発想が必要。
```

---

## ツイート4

```
【失敗③】データ移行を舐めてる

「今のシステムのデータを移すだけでしょ？」

これが一番危険な発言。

・勘定科目体系が違う
・過去の仕訳が汚い（同じ内容なのに科目がバラバラ）
・マスタが整備されていない

データ移行は「コピペ」じゃない。
クレンジングと設計が必要。
ここに工数の3割が消えることもある。
```

---

## ツイート5

```
【失敗④】「稼働=ゴール」と思ってる

本番稼働は通過点。

稼働後1〜3ヶ月が一番しんどい。
・現場が慣れていない
・エラーが頻発する
・「前のシステムの方が良かった」という声が出る

この時期に手厚くフォローできるか、
「定着化」まで支援できるかが成否を分ける。
```

---

## ツイート6

```
【失敗⑤】経理部門がプロジェクトに入っていない

「IT部門とベンダーに任せた」

会計システムなのに経理が主体じゃない、
というプロジェクトは高確率で失敗する。

・仕訳のルールを誰が決めるか
・消費税区分をどう設計するか
・月次決算のフローをどう変えるか

全部、会計の知識がないと決められない。
```

---

## ツイート7

```
【失敗⑥】ベンダーに「おまかせ」する

ベンダーは「導入のプロ」であって
「あなたの会社の業務のプロ」ではない。

・自社のビジネスモデルを説明できる人が必要
・「なぜこの業務が必要か」を伝えられる人が必要

ベンダーをうまく使えるのは、
自社の業務をちゃんと理解してる人だけ。
```

---

## ツイート8（まとめ・CTA）

```
まとめると、ERP導入を成功させる要素は：

✅ 現場を巻き込んだ要件定義
✅ カスタマイズを最小化する勇気
✅ データ移行への工数確保
✅ 稼働後の定着化支援
✅ 経理部門が主体になる
✅ ベンダーを「使う」姿勢

簿記では「プロジェクトマネジメント」を教えてくれない。
でもこれが会計システムの専門家に必要な力だと思う。

参考になったらRT・保存してもらえると嬉しいです🙏
```
